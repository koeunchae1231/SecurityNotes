# 4-1. 접근 통제(Access Control)

- 정당한 사용자에게는 권한을 부여하고, 비인가 사용자의 접근은 거부하는 것

## 4-1-1. 접근 통제 개요

### 1) 접근(Access)의 구성 요소

1. **주체(Subject)**
   - 자원 접근을 요구하는 능동적인 개체
   - 예: 사용자, 프로세스

2. **객체(Object)**
   - 자원을 가진 수동적인 개체
   - 예: 파일, 데이터베이스, 프린터

3. **접근(Access)**
   - 주체와 객체 사이에서 발생하는 정보의 흐름

### 2) 정보 접근의 단계

1. **식별(Identification)**
   - 사용자가 시스템에 자신의 신원을 밝히는 행위
   - 사용자를 고유하게 구분하며 책임 추적성 분석의 기초가 된다.

2. **인증(Authentication)**
   - 사용자가 주장한 신원이 실제로 맞는지 시스템이 확인하는 단계

3. **인가(Authorization)**
   - 인증된 사용자의 접근 권한 유무를 판별하고 권한을 부여하는 단계

### 3) 접근 통제의 정의

#### (1) 통제 목적

- 주체의 접근으로부터 객체의 기밀성·무결성·가용성(CIA)을 보장한다.

#### (2) 통제 활동

- 비인가 접근 감시
- 접근을 요구하는 이용자 식별
- 정당한 이용자인지 확인

### 4) 접근 통제 원칙

1. **최소 권한 원칙(Principle of Least Privilege)**
   - 업무 수행에 필요한 최소한의 권한만 부여하여 권한 남용을 방지한다.

2. **직무 분리(Separation of Duties)**
   - 하나의 업무가 한 사람에 의해 전부 처리되지 않도록 권한과 절차를 분리한다.

### 5) 참조 모니터(Reference Monitor)

- 주체의 객체 접근 요청을 중재하고 접근 허용 여부를 결정하는 보안 메커니즘
- 운영체제에서는 보안 커널(Security Kernel)의 핵심 개념으로 구현된다.

#### (1) 완전성(Completeness)

- 모든 접근 요청을 검사해야 하며 우회할 수 없어야 한다.

#### (2) 격리(Isolation)

- 부정한 변경이나 조작이 불가능해야 한다(Tamper-proof).

#### (3) 검증성(Verifiability)

- 분석과 테스트가 가능할 정도로 충분히 단순하고 작아야 한다.
- Simple, Small, Understandable

## 4-1-2. 접근 통제 정책

- 사용자의 접근 권한을 어떤 기준으로 결정할 것인지 정의한 정책

### 1) 접근 통제 정책 비교

| 구분 | MAC | DAC | RBAC |
|---|---|---|---|
| 의미 | 강제적 접근 통제 | 자율적 접근 통제 | 역할 기반 접근 통제 |
| 권한 부여자 | 중앙 관리자·시스템 | 객체 소유자(Data Owner) | 시스템 관리자 |
| 접근 결정 기준 | 보안 레이블과 규칙 | 사용자 신원(Identity) | 역할(Role) |
| OSI 보안 구조 | 규칙 기반 정책 | 신분 기반 정책 | 역할·업무 기반 정책 |
| 오렌지북 | B 등급 | C 등급 | 별도 분류 대상 아님 |
| 장점 | 안전하고 중앙집중적 관리 가능 | 유연하고 구현이 쉬움 | 권한 관리가 쉽고 직무 분리에 적합 |
| 단점 | 구현·운영이 어렵고 비용이 높음 | 트로이목마와 ID 도용에 취약 | 역할 외 다양한 조건을 정책에 반영하기 어려움 |
| 적용 사례 | 군사·정부 기밀 시스템 | UNIX, 일반 운영체제, DBMS | 기업 업무 시스템, 의료정보 시스템 |

### 2) RBAC(Role-Based Access Control)

- 사용자에게 역할(Role) 단위로 권한을 할당하고 관리하는 방식
- **Role:** 역할에 따라 묶어 놓은 권한의 집합

#### (1) 장점

- 역할을 기준으로 권한을 일괄 관리할 수 있어 관리 비용이 감소한다.
- 권한을 논리적·독립적으로 할당하거나 회수할 수 있어 보안 관리가 단순하다.
- 최소 권한 원칙과 직무 분리를 구현하기에 적합하다.

### 3) MAC(Mandatory Access Control)

- 데이터 접근 여부를 시스템이 정한 강제적인 규칙에 따라 결정하는 방식
- OSI 보안 구조에서 규칙 기반 정책(Rule-based Policy)에 해당한다.
- 주체의 비밀 취급 인가 레이블과 객체의 민감도 레이블을 비교한다.
- 관리자에 의해 권한이 할당·해제되며, 관리자만 자원의 보안 범주를 변경할 수 있다.

> **Clearance Label:** 주체의 비밀 취급 인가 레이블 또는 사용자 보안 등급  
> **Sensitivity Label:** 객체의 민감도 레이블 또는 객체 보안 등급

#### (1) Rule-based MAC

- 주체와 객체의 특성과 관련된 특정 규칙에 따라 접근을 통제한다.

#### (2) Administratively-directed MAC

- 시스템 관리자가 객체 접근 권한을 설정하고 통제한다.

#### (3) CBP(Compartment-Based Policy)

- 특정 객체 집합을 다른 객체 집합과 구획(Compartment)으로 분리한다.
- 같은 보안 수준에서도 서로 다른 구획에 따라 접근 가능 여부가 달라질 수 있다.

#### (4) MLP(Multi-Level Policy)

- 각 객체에 허용 보안 등급을 할당하여 접근을 통제한다.
- 예: Top Secret, Secret, Confidential, Unclassified
- 미국 국방성 컴퓨터 보안 평가지표에 사용되며 Bell-LaPadula 모델로 표현할 수 있다.

### 4) DAC(Discretionary Access Control)

- 객체의 소유자가 데이터에 대한 접근 권한을 자율적으로 부여하는 방식
- OSI 보안 구조에서 신분 기반 정책(Identity-based Policy)에 해당한다.
- 융통성이 높아 UNIX와 DBMS 등 일반적인 시스템에서 널리 사용된다.
- ACL을 이용하여 Read, Write, Execute 등의 권한을 관리한다.
- MAC의 단점을 극복하기 위해 등장한 방식은 아니다.

#### (1) Identity-based DAC

- 주체와 객체의 ID를 기준으로 접근을 통제한다.
- 주로 UNIX 계열 시스템에서 사용된다.

#### (2) User-directed DAC

- 객체 소유자가 접근 권한을 직접 설정하거나 변경할 수 있다.

### 5) Non-DAC(Non-Discretionary Access Control)

- 주체의 역할이나 업무에 따라 접근 가능한 객체를 지정하는 비임의적 접근 통제
- OSI 보안 구조에서 역할·업무 기반 정책(Role/Task-based Policy)에 해당한다.
- 중앙 관리자 또는 중앙 권한 기관이 접근 규칙을 지정한다.
- 사용자별 접근 통제 규칙을 각각 설정할 필요가 없다.

#### (1) RBAC(Role-Based Access Control)

- 사용자의 역할에 따라 접근 권한을 부여한다.

#### (2) Lattice-based Non-DAC

- 역할에 할당된 민감도 수준과 주체·객체의 관계에 따라 접근을 통제한다.
- 정보 흐름을 제어하며 상한(Upper Bound)과 하한(Lower Bound)을 이용할 수 있다.

#### (3) Task-based Non-DAC

- 조직 내 개인에게 부여된 임무를 기준으로 접근을 통제한다.
- 알 필요성의 원칙(Need-to-Know Principle)을 적용한다.

## 4-1-3. 접근 통제 방법

### 1) Capability List

- **주체(Subject) 중심** 접근 통제 방식
- 주체마다 접근 가능한 객체와 권한을 링크드 리스트(Linked List) 형태로 관리한다.
- 각 주체를 기준으로 권한을 확인할 수 있지만, 주체별 객체 목록이 존재하므로 객체 기준 권한 탐색에는 시간이 증가할 수 있다.

```text
사용자 A → [파일 1, RW] → [파일 2, R] → [프린터, E] → NULL
```

### 2) ACL(Access Control List)

- **객체(Object) 중심** 접근 통제 방식
- 각 객체마다 접근 가능한 사용자와 권한을 저장한다.
- 구분해야 할 사용자가 적고 권한 분포가 안정적인 환경에 적합하다.
- 사용자의 추가·삭제와 권한 변경이 빈번한 환경에서는 관리가 복잡해질 수 있다.

```text
파일 A
- 사용자 A: RW
- 사용자 B: R
- 관리자: RWE
```

## 4-1-4. 접근 통제 매트릭스 구현 방식

- 접근 통제 매트릭스는 행에 주체, 열에 객체를 배치하고 두 항목의 교차점에 접근 권한을 표현한다.

| 주체 \ 객체 | 파일 A | 파일 B | 프린터 |
|---|---|---|---|
| 사용자 A | R, W | R | E |
| 사용자 B | R | - | E |
| 관리자 | R, W, D | R, W, D | E |

> R: Read, W: Write, D: Delete, E: Execute

### 1) ACL(Access Control List)

- 객체를 기준으로 허용된 주체의 이름과 권한을 저장한다.
- 접근 통제 매트릭스의 각 열을 객체별 목록으로 구현한 이름 기반 접근 통제 방식이다.

### 2) CDAC(Content-Dependent Access Control)

- 객체나 데이터의 내용(Content)에 따라 접근 여부를 결정하는 방식
- 데이터베이스에서 많이 사용되며, 입력되거나 저장된 정보의 내용을 비교하여 접근을 통제한다.

### 3) Restricted Interface(Constrained User Interface)

- 사용자가 이용할 수 있는 기능·메뉴·명령어 자체를 제한하는 방식
- 특정 기능이나 자원에 대한 권한이 없으면 해당 접근 요청을 수행할 수 없다.
- 사용자에게 허용된 기능만 인터페이스에 제공한다.

## 4-1-5. 접근 통제 모델

### 1) Bell-LaPadula 모델

- 기밀성(Confidentiality)을 보호하기 위한 모델
- 높은 보안 등급의 정보가 낮은 보안 등급으로 유출되는 것을 통제한다.
- 보안 등급과 범주를 사용하는 최초의 수학적 강제적 접근 통제 모델이다.

#### (1) No Read Up

- NRU 또는 ss-property(Simple Security Property)
- 주체는 자신보다 높은 등급의 객체를 읽을 수 없다.

#### (2) No Write Down

- NWD 또는 *-property(Star Property)
- 주체는 자신보다 낮은 등급의 객체에 쓸 수 없다.

#### (3) Strong *-property

- 주체는 자신과 보안 등급이 다른 객체에 대해 읽거나 쓸 수 없다.

| 객체의 등급 | 읽기 권한 | 쓰기 권한 | Strong *-property |
|---|---|---|---|
| 주체보다 높음 | 통제(No Read Up) | 가능(Write Up) | 통제 |
| 주체와 같음 | 가능 | 가능 | 가능 |
| 주체보다 낮음 | 가능(Read Down) | 통제(No Write Down) | 통제 |

> **핵심:** 읽기는 위로 금지, 쓰기는 아래로 금지

### 2) Biba 모델

- 무결성(Integrity)을 보호하기 위한 모델
- 낮은 무결성 등급의 정보가 높은 무결성 등급에 영향을 주는 것을 통제한다.

#### (1) No Read Down

- ss-property(Simple Integrity Property)
- 주체는 자신보다 낮은 무결성 등급의 객체를 읽을 수 없다.

#### (2) No Write Up

- *-property(Star Integrity Property)
- 주체는 자신보다 높은 무결성 등급의 객체에 쓸 수 없다.

| 객체의 등급 | 읽기 권한 | 쓰기 권한 |
|---|---|---|
| 주체보다 높음 | 가능(Read Up) | 통제(No Write Up) |
| 주체와 같음 | 가능 | 가능 |
| 주체보다 낮음 | 통제(No Read Down) | 가능(Write Down) |

> **핵심:** 읽기는 아래로 금지, 쓰기는 위로 금지

### 3) Clark-Wilson 모델

- 상업용 시스템과 애플리케이션의 무결성을 보호하기 위한 모델
- 사용자가 객체를 직접 수정하지 않고 허가된 프로그램을 통해서만 접근하도록 한다.
- 업무 절차에 따라 데이터를 수정하며 직무 분리를 지원한다.
- 내부 일관성은 시스템의 정상적인 이용을 보장하고, 외부 일관성은 감사와 현실 세계의 데이터 일치를 확인하는 데 활용된다.

```text
주체 → 허가된 프로그램(TP) → 객체
```

#### (1) IVP(Integrity Verification Procedure)

- 무결성 검증 절차
- 데이터가 정해진 무결성 조건을 만족하고 정상적인 상태인지 검사한다.

#### (2) TP(Transformation Procedure)

- 변환 절차
- 데이터를 한 무결한 상태에서 다른 무결한 상태로 변경하는 허가된 프로그램 또는 공식적인 수정 절차

### 4) 만리장성 모델(Chinese Wall / Brewer-Nash)

- 상업용 환경의 기밀성 보호를 위한 접근 통제 모델
- 서로 상충하는 관계에 있는 객체나 기업 정보 사이의 접근을 통제한다.
- 사용자가 이전에 접근한 정보와 이해충돌이 발생하는 다른 정보에는 접근하지 못하도록 한다.
- 이익의 상충을 방지하기 위한 동적 접근 통제 정책이다.

> **이해충돌(Conflict of Interest):** 경쟁 관계나 상충하는 이해관계를 가진 기업·조직의 정보를 한 사람이 동시에 취급하여 공정성과 기밀성이 훼손될 수 있는 상황

## 4-1-6. 핵심 비교

| 모델 | 보호 목표 | 핵심 규칙·특징 |
|---|---|---|
| Bell-LaPadula | 기밀성 | No Read Up, No Write Down |
| Biba | 무결성 | No Read Down, No Write Up |
| Clark-Wilson | 상업용 무결성 | TP, IVP, 직무 분리 |
| Chinese Wall | 상업용 기밀성 | 이해충돌 정보의 동시 접근 금지 |

```text
Bell-LaPadula: 읽기 ↑ X / 쓰기 ↓ X
Biba:           읽기 ↓ X / 쓰기 ↑ X
Clark-Wilson:   TP로 수정 / IVP로 검사
Chinese Wall:   경쟁 관계 정보 동시 접근 금지
```
