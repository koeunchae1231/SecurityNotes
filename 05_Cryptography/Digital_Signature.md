# 4. 전자서명

- 비대칭키 암호 방식을 이용하여 전자서명 생성키로 생성한 정보
- 메시지의 무결성과 서명자의 인증 및 부인방지를 제공한다.
- 전자서명 자체는 기밀성을 제공하지 않는다.

## 1) 특징

### (1) 서명자 인증(Authentication)

- 전자서명을 생성한 서명자를 검증할 수 있다.
- 검증에는 서명자의 공개키를 사용한다.

### (2) 부인방지(Non-Repudiation)

- 서명자는 자신이 전자서명을 생성한 사실을 사후에 부인하기 어렵다.

### (3) 위조 불가(Unforgeable)

- 서명자의 개인키 없이는 정상적인 전자서명을 생성하기 어렵다.

### (4) 변경 불가(Unalterable)

- 서명 후 원문이나 전자서명이 변경되면 검증 과정에서 이를 확인할 수 있다.

### (5) 재사용 불가(Not-Reusable)

- 한 문서의 해시값을 기반으로 생성한 전자서명은 다른 문서의 서명으로 재사용할 수 없다.

## 2) 기능

### (1) 사용자 인증

- 서명문의 서명자가 누구인지 제3자가 확인할 수 있다.
- 비대칭키 암호 기법을 이용한다.

### (2) 메시지 인증

- 메시지 내용의 무결성을 보증한다.
- 해시 함수를 이용한다.

---

## 4-1. 전자서명 과정

### 1) 전자서명 생성 과정(송신자)

#### (1) 해시값 생성

- 원본 메시지를 해시 함수에 입력하여 해시값을 생성한다.

#### (2) 전자서명 생성

- 생성된 해시값에 송신자의 개인키를 이용해 서명 연산을 수행한다.
- RSA 전자서명 방식을 예로 들면 송신자의 RSA 개인키로 전자서명을 생성한다.

#### (3) 전자서명 암호화

- 기밀성이 필요한 경우 원본 메시지와 전자서명을 대칭 세션 키로 암호화한다.
- 대칭키 알고리즘으로 AES나 DES 등을 사용할 수 있다.

#### (4) 전자봉투 생성

- 대칭 세션 키로 암호화된 원본 메시지와 전자서명
- 수신자의 공개키로 암호화된 대칭 세션 키
- 위 두 항목을 함께 전송하여 전자봉투를 구성한다.

```text
원본 메시지
    ↓ 해시 함수
해시값
    ↓ 송신자의 개인키(RSA 등)로 서명
전자서명

원본 메시지 + 전자서명
    ↓ 대칭 세션 키(AES·DES 등)로 암호화
암호화된 데이터

대칭 세션 키
    ↓ 수신자의 공개키(RSA 등)로 암호화
암호화된 세션 키

암호화된 데이터 + 암호화된 세션 키 = 전자봉투
```

### 2) 전자서명 확인·검증 과정(수신자)

#### (1) 대칭 세션 키 복호화

- 전자봉투에서 암호화된 대칭 세션 키를 수신자의 개인키로 복호화한다.

#### (2) 원본 메시지와 전자서명 복호화

- 확보한 대칭 세션 키로 암호화된 원본 메시지와 전자서명을 복호화한다.
- 복호화된 원본 메시지를 해시 함수에 입력하여 해시값 A를 생성한다.

#### (3) 전자서명 검증

- 송신자의 공개키로 전자서명을 검증하여 서명자가 생성한 해시값 B를 확인한다.

#### (4) 해시값 비교

- 해시값 A와 해시값 B가 같으면 무결성, 인증, 부인방지가 성립한다.
- 두 값이 다르면 메시지 변조 또는 서명 위조를 의심할 수 있다.

### 3) 키 사용 정리

| 구분 | 키(Key) | 설명 |
|---|---|---|
| 송신자 | 송신자의 개인키 | 전자서명 생성 |
| 송신자 | 수신자의 공개키 | 대칭 세션 키 암호화 |
| 수신자 | 수신자의 개인키 | 암호화된 대칭 세션 키 복호화 |
| 수신자 | 송신자의 공개키 | 전자서명 확인·검증 |

## 4-2. 전자서명 기법의 종류

### 1) RSA 전자서명

- RSA 공개키 암호 알고리즘을 이용하여 메시지에 전자서명한다.
- 송신자의 개인키로 서명을 생성하고 송신자의 공개키로 검증한다.
- 큰 수의 소인수분해가 어렵다는 성질을 안전성의 기반으로 사용한다.
- 암호화와 전자서명에 모두 사용할 수 있다.

### 2) ElGamal 전자서명

- 이산대수 문제의 어려움을 기반으로 하는 전자서명 방식이다.
- 서명자는 자신의 개인키로 전자서명을 생성하고 공개키로 검증한다.
- ElGamal 방식은 공개키 암호화와 전자서명에 모두 응용할 수 있다.

### 3) Schnorr 전자서명

- 이산대수 문제를 기반으로 하는 전자서명 방식이다.
- 서명 크기와 계산량을 줄이기 위해 제안된 방식이다.
- IC 카드와 같이 자원이 제한된 환경에 적합하다.

### 4) DSS(Digital Signature Standard)

- 미국의 전자서명 표준이다.
- DSS에서 사용하는 대표적인 알고리즘이 DSA(Digital Signature Algorithm)이다.
- DSA는 ElGamal 전자서명을 개선한 방식이며 이산대수 문제를 기반으로 한다.
- RSA와 달리 암호화나 키 교환을 지원하지 않고 전자서명 생성과 검증만을 목적으로 한다.
- 서명 검증 부하를 줄이기 위해 계산량을 줄인 구조를 사용한다.

### 5) KCDSA(Korean Certificate-based Digital Signature Algorithm)

- 1996년에 개발된 국내 인증서 기반 전자서명 알고리즘이다.
- 1998년 한국정보통신기술협회에서 국가 표준으로 제정되었다.
- 이산대수 문제를 안전성의 기반으로 사용한다.
- 국내 인증서 기반 전자서명 환경에 활용되었다.

### 6) ECC 전자서명

- 타원곡선 암호(ECC)를 기반으로 하는 전자서명 방식이다.
- 대표적인 알고리즘으로 ECDSA(Elliptic Curve Digital Signature Algorithm)가 있다.
- 동일한 보안 수준에서 RSA보다 짧은 키를 사용할 수 있다.
- 키와 서명의 크기가 작아 전자서명 생성과 검증이 효율적이다.
