# 4. 전자서명(Digital Signature)

- 비대칭키 암호와 해시 함수를 이용하여 서명자의 신원과 메시지의 무결성을 검증하는 기술
- 송신자는 자신의 개인키로 서명을 생성하고, 수신자는 송신자의 공개키로 서명을 검증한다.
- 무결성(Integrity), 인증(Authentication), 부인방지(Non-Repudiation)를 제공한다.
- 전자서명 자체는 기밀성(Confidentiality)을 제공하지 않는다.

## 4-1. 전자서명의 특징

1. **서명자 인증(Authentication)**
   - 전자서명을 생성한 서명자가 누구인지 검증할 수 있다.
   - 검증에는 서명자의 공개키를 사용한다.

2. **부인방지(Non-Repudiation)**
   - 서명자는 자신이 전자서명을 생성한 사실을 사후에 부인하기 어렵다.

3. **위조 방지(Unforgeable)**
   - 서명자의 개인키를 알지 못하면 정상적인 전자서명을 생성하기 어렵다.

4. **변경 탐지(Unalterable)**
   - 서명 후 원문이나 전자서명이 변경되면 검증 과정에서 이를 확인할 수 있다.

5. **재사용 방지(Not Reusable)**
   - 전자서명은 특정 문서의 해시값을 이용하여 생성하므로 다른 문서의 서명으로 재사용할 수 없다.

---

## 4-2. 전자서명의 기능

### 1) 사용자 인증

- 서명문을 생성한 사람이 해당 서명자임을 제3자가 확인할 수 있다.
- 비대칭키 암호 방식의 개인키와 공개키를 이용한다.

### 2) 메시지 인증

- 메시지가 전송 과정에서 변경되지 않았음을 검증한다.
- 원본 메시지에 해시 함수를 적용하여 생성한 해시값을 이용한다.

> **핵심:** 개인키는 서명 생성에 사용하고, 공개키는 서명 검증에 사용한다.

---

## 4-3. 전자서명 생성 및 검증 과정

### 1) 전자서명 생성 과정(송신자)

1. **원본 메시지 작성**
   - 송신자가 수신자에게 전달할 원본 메시지를 작성한다.

2. **해시값 생성**
   - 원본 메시지를 SHA-256 등의 해시 함수에 입력하여 고정 길이의 해시값을 생성한다.

3. **전자서명 생성**
   - 생성한 해시값에 송신자의 개인키를 이용하여 서명 연산을 수행한다.
   - RSA 서명 방식을 예로 들면 송신자의 RSA 개인키로 서명값을 생성한다.

4. **메시지와 전자서명 전송**
   - 기밀성이 필요하지 않다면 원본 메시지와 전자서명을 함께 전송한다.

```text
원본 메시지
    ↓ 해시 함수
메시지 해시값
    ↓ 송신자의 개인키로 서명
전자서명 생성

원본 메시지 + 전자서명 전송
```

### 2) 전자서명 확인·검증 과정(수신자)

1. **수신 메시지의 해시값 생성**
   - 수신한 원본 메시지에 송신자와 동일한 해시 함수를 적용하여 해시값 A를 생성한다.

2. **전자서명 검증**
   - 송신자의 공개키로 전자서명을 검증하여 서명자가 생성한 해시값 B를 확인한다.

3. **두 해시값 비교**
   - 해시값 A와 해시값 B가 같으면 메시지의 무결성과 서명자의 신원을 확인할 수 있다.
   - 두 값이 다르면 메시지가 변경되었거나 전자서명이 올바르지 않은 것이다.

```text
수신한 원본 메시지
    ↓ 동일한 해시 함수
해시값 A

수신한 전자서명
    ↓ 송신자의 공개키로 검증
해시값 B

해시값 A == 해시값 B
    ├─ 동일: 무결성·인증·부인방지 확인
    └─ 다름: 메시지 변경 또는 서명 위조 의심
```

### 3) 키 사용 정리

| 구분 | 사용하는 키 | 목적 |
|---|---|---|
| 송신자 | 송신자의 개인키 | 전자서명 생성 |
| 수신자 | 송신자의 공개키 | 전자서명 검증 |
| 송신자 | 수신자의 공개키 | 기밀성을 위한 세션 키 암호화 |
| 수신자 | 수신자의 개인키 | 암호화된 세션 키 복호화 |

---

## 4-4. 전자봉투(Digital Envelope)

- 전자서명은 무결성·인증·부인방지를 제공하지만, 원본 메시지의 기밀성은 제공하지 않는다.
- 기밀성까지 확보하려면 전자서명과 하이브리드 암호 방식을 결합한 전자봉투를 사용한다.
- 전자봉투에서는 실제 데이터는 빠른 대칭키로 암호화하고, 대칭키는 수신자의 공개키로 암호화한다.

### 1) 전자봉투 생성 과정(송신자)

1. 원본 메시지를 해시하여 해시값을 생성한다.
2. 해시값을 송신자의 개인키로 서명하여 전자서명을 생성한다.
3. 임의의 대칭 세션 키를 생성한다.
4. 세션 키로 원본 메시지와 전자서명을 암호화한다.
5. 세션 키를 수신자의 공개키로 암호화한다.
6. 암호화된 데이터와 암호화된 세션 키를 함께 전송한다.

```text
원본 메시지
    ↓ 해시
해시값
    ↓ 송신자 개인키
전자서명

원본 메시지 + 전자서명
    ↓ 대칭 세션 키(AES·DES 등)
암호화된 데이터

대칭 세션 키
    ↓ 수신자 공개키(RSA 등)
암호화된 세션 키

암호화된 데이터 + 암호화된 세션 키 = 전자봉투
```

### 2) 전자봉투 확인 과정(수신자)

1. 수신자의 개인키로 암호화된 세션 키를 복호화한다.
2. 확보한 세션 키로 암호화된 원본 메시지와 전자서명을 복호화한다.
3. 복호화된 원본 메시지를 해시하여 해시값 A를 생성한다.
4. 송신자의 공개키로 전자서명을 검증하여 해시값 B를 확인한다.
5. 두 해시값을 비교하여 무결성·인증·부인방지를 확인한다.

> **구분:** 송신자의 개인키는 서명에 사용하고, 수신자의 공개키는 세션 키 암호화에 사용한다.

---

## 4-5. 전자서명 기법의 종류

### 1) RSA 전자서명

- RSA 공개키 암호 알고리즘을 이용한 전자서명 방식
- 송신자의 개인키로 서명을 생성하고 송신자의 공개키로 검증한다.
- 큰 수의 소인수분해가 어렵다는 성질을 안전성의 기반으로 사용한다.
- 암호화와 전자서명에 모두 활용할 수 있다.

### 2) ElGamal 전자서명

- 이산대수 문제의 어려움을 기반으로 하는 전자서명 방식
- 서명자는 자신의 개인키로 서명을 생성하고 공개키로 검증한다.
- ElGamal 방식은 공개키 암호화와 전자서명에 모두 응용할 수 있다.

### 3) Schnorr 전자서명

- 이산대수 문제를 기반으로 하는 전자서명 방식
- 서명 크기와 계산량을 줄이도록 설계되어 스마트카드와 같은 제한된 환경에 적합하다.
- 이후 여러 전자서명 방식의 기반이 되었다.

### 4) DSS(Digital Signature Standard)

- 미국의 전자서명 표준
- DSS에서 사용하는 대표적인 알고리즘이 DSA(Digital Signature Algorithm)이다.
- DSA는 ElGamal 서명 방식을 개선한 구조로 이산대수 문제를 기반으로 한다.
- 암호화나 키 교환이 아니라 전자서명 생성과 검증만을 목적으로 한다.

### 5) KCDSA(Korean Certificate-based Digital Signature Algorithm)

- 국내에서 개발된 인증서 기반 전자서명 알고리즘
- 이산대수 문제를 안전성의 기반으로 사용한다.
- 국내 전자서명 표준으로 제정되어 인증서 기반 서명 환경에 활용되었다.

### 6) ECDSA(Elliptic Curve Digital Signature Algorithm)

- 타원곡선 암호(ECC)를 기반으로 하는 전자서명 알고리즘
- 동일한 보안 수준에서 RSA보다 짧은 키를 사용할 수 있다.
- 키와 서명의 크기가 작아 저장 공간과 통신량이 제한된 환경에 적합하다.

### 7) 전자서명 알고리즘 비교

| 방식 | 기반 문제 | 암호화 지원 | 특징 |
|---|---|---|---|
| RSA | 소인수분해 | 가능 | 암호화와 전자서명 모두 사용 가능 |
| ElGamal | 이산대수 | 가능 | 암호화와 전자서명에 응용 가능 |
| Schnorr | 이산대수 | 전자서명 중심 | 서명 크기와 계산량 감소 |
| DSA/DSS | 이산대수 | 불가 | 전자서명 전용 |
| KCDSA | 이산대수 | 전자서명 중심 | 국내 인증서 기반 전자서명 표준 |
| ECDSA | 타원곡선 이산대수 | 전자서명 전용 | 짧은 키로 높은 보안성 제공 |

---

## 4-6. 전자서명과 암호화의 차이

| 구분 | 전자서명 | 공개키 암호화 |
|---|---|---|
| 처리 대상 | 메시지의 해시값 | 원문 또는 대칭 세션 키 |
| 처리 키 | 송신자의 개인키 | 수신자의 공개키 |
| 확인 키 | 송신자의 공개키 | 수신자의 개인키 |
| 주요 목적 | 무결성·인증·부인방지 | 기밀성 |

### 핵심

```text
전자서명
송신자 개인키 → 서명 생성
송신자 공개키 → 서명 검증

공개키 암호화
수신자 공개키 → 암호화
수신자 개인키 → 복호화
```

---

## 4-7. 시험 빈출 포인트

- 전자서명은 원문 전체가 아니라 원문의 해시값에 대해 생성한다.
- 서명 생성에는 송신자의 개인키를 사용한다.
- 서명 검증에는 송신자의 공개키를 사용한다.
- 전자서명은 무결성·인증·부인방지를 제공하지만 기밀성은 제공하지 않는다.
- 기밀성까지 필요하면 전자봉투를 사용한다.
- 전자봉투의 원문 암호화에는 AES·DES 등의 대칭키 알고리즘을 사용할 수 있다.
- 전자봉투의 세션 키 암호화에는 RSA 등의 공개키 알고리즘을 사용할 수 있다.
- DSA와 ECDSA는 전자서명 전용 알고리즘이다.
- RSA는 공개키 암호화와 전자서명에 모두 사용할 수 있다.
